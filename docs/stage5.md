# Этап 5 — Раздача коллегам (и автообновление)

ТЗ для этого этапа просит только «сборка, инструкция по установке и логину CLI» —
без обновлений вообще. Пользователь явно попросил обновления тоже: с парой друзей и
нерегулярными багфиксами ручная пересылка `.exe` каждый раз неудобна, поэтому сразу
взяли официальный механизм, а не самописный.

## Как это работает

- **`tauri-plugin-updater`** (Rust) + **`@tauri-apps/plugin-updater`** (JS) — проверяет
  `endpoints` из `src-tauri/tauri.conf.json` на `latest.json`, сверяет версию, при
  наличии новой — скачивает и ставит инсталлятор, подпись проверяется локальным
  публичным ключом (тот же `tauri.conf.json`, поле `plugins.updater.pubkey`).
- **`tauri-plugin-process`** — `relaunch()` после успешной установки, чтобы приложение
  перезапустилось на новой версии без ручного действия пользователя.
- **Хостинг релизов — GitHub Releases** конкретного репозитория (публичного — иначе
  клиенту для скачивания нужен был бы GitHub-токен, зашитый в саму программу у
  каждого друга; это обсуждали и осознанно выбрали публичный репозиторий).
- **`.github/workflows/release.yml`** — при пуше тега `v*` собирает Windows-инсталлятор
  (`tauri-apps/tauri-action`), подписывает ключом обновлений и создаёт **черновик**
  релиза на GitHub (`releaseDraft: true`) — чтобы можно было проверить/дополнить текст
  релиза, прежде чем он станет видимым и его подхватит автообновление у уже
  установленных копий.
- **`requireSignedVersion: true`** в конфиге обновлятора — защита от даунгрейд-атаки:
  подпись должна явно содержать ту версию, для которой её делали, иначе обновление
  отклоняется (актуально, раз `latest.json` отдаётся по HTTPS, но сам по себе не
  подписан — подписан только файл инсталлятора).
- **Баннер в `index.html`/`main.ts`** (`#update-banner`) — проверка один раз при старте
  (`checkForUpdatesOnce`), висит поверх всего независимо от того, сессия активна или
  открыт лаунчер. Периодического повторного опроса нет — приложение обычно
  перезапускают, а не держат сутками; если понадобится, добавить легко.

## Ключ подписи обновлений

Сгенерирован локально: `.tauri-keys/termiinal-updater.key` (приватный,
зашифрован паролем) + `.tauri-keys/termiinal-updater.key.pub` (публичный, его
содержимое уже вписано в `tauri.conf.json`). Пароль — `.tauri-keys/updater-key-password.txt`.

**Вся папка `.tauri-keys/` — в `.gitignore`, НИКОГДА не коммитится**, даже в публичный
репозиторий. Если приватный ключ или пароль потеряются — старые установленные копии
смогут обновляться только после генерации НОВОГО ключа и смены `pubkey` в конфиге, то
есть по сути придётся попросить всех переустановить вручную один раз.

## Репозиторий

Публичный, `https://github.com/Pakochka/termiinal` — создан пользователем, код туда
запушен (ветка `main`, история смержена с автосозданным GitHub README через
`--allow-unrelated-histories`, оставили свой README.md). Эндпоинт обновлятора в
`src-tauri/tauri.conf.json` уже указывает на него.

**Остался один шаг, который без доступа к GitHub-аккаунту не автоматизировать:**
в Settings → Secrets and variables → Actions добавить два секрета (значения — печатать
их в терминал через Claude Code запретил сам классификатор auto mode, это и правильно
для секрета; открыть файлы и скопировать значения нужно руками):
- `TAURI_SIGNING_PRIVATE_KEY` — содержимое `.tauri-keys/termiinal-updater.key`;
- `TAURI_SIGNING_PRIVATE_KEY_PASSWORD` — содержимое
  `.tauri-keys/updater-key-password.txt`.

Без них CI на `tauri-apps/tauri-action` не сможет подписать релиз при пуше тега.

## Как выпускать релиз

1. Поднять версию в `src-tauri/tauri.conf.json` (`"version"`) и `package.json`.
2. Закоммитить, затем `git tag vX.Y.Z && git push origin vX.Y.Z`.
3. CI соберёт инсталлятор и создаст **черновик** релиза на GitHub — проверить/дополнить
   описание и опубликовать его руками (Publish release).
4. У уже установленных копий при следующем запуске появится баннер «доступно
   обновление», установка — в один клик, с автоперезапуском.

Первую установку (у кого программы ещё нет) это не заменяет — им всё равно нужно один
раз скачать инсталлятор со страницы релиза и поставить вручную; дальше обновления идут
сами.

## Переименование и брендинг

Проект назывался `terminal-mentor`, переименован в `termiinal` («терминал» + «ИИ») —
переименовано везде: package.json, Cargo.toml (крейт `termiinal_lib`), tauri.conf.json
(`productName`/заголовок окна/`identifier` `com.pakochka.termiinal`), ключи localStorage
(`termiinal:...`), ключ подписи обновлений на диске. README.md переписан: функционал и
что нужно для работы — наверх, техническая часть — вниз.

**Акцентный цвет приложения перекрашен под лого** — пользователь принёс набросок лого
(игра слов: двойная "ii" в "Term**ii**nal" стилизована под пару глаз, скобки вокруг —
брови/рамка лица) и попросил сделать логотип в шапке сессии с анимацией, перекрасив всё
приложение под его цвет для согласованности бренда.

- Точный цвет снят не на глаз, а замером пикселей скриншота-наброска через
  `System.Drawing` в PowerShell (сканировали распределение цветов по всему изображению,
  не одну точку) — доминирующий акцент `#10E0A8` (мятно-бирюзовый), фон плашки `#151515`,
  текст `#F2F2F2`. Было `--accent: #5aa8ff` (синий) — заменено везде, включая то, что
  не через CSS-переменную (курсор/выделение xterm.js задаются JS-объектом темы, не CSS).
- **Лого-индикатор** (`#session-logo` в `index.html`, стили в `styles.css`, логика в
  `main.ts`) заменил текстовое саммари "user@host" в шапке сессии — сам хост теперь
  виден в подсказке (`title`) при наведении, а на месте текста — живой значок "глаз"
  агента (`( ii )` из текста + две брови-SVG, переключаемые по `data-mood`).
  - Собран из текста + CSS + маленьких inline SVG (три пары бровей — по одной на
    настроение), а не картинкой/GIF: так он резкий на любом масштабе и его реально
    анимировать CSS-переходами прозрачности между состояниями, плюс периодическое
    моргание (`@keyframes logo-blink`) для живости в состоянии покоя.
  - Три настроения привязаны к уже отслеживаемому состоянию агента, не к отдельному
    декоративному таймеру: `idle` ("смотрит в шелл") — агент свободен; `thinking`
    ("думает") — `agentBusy`, от отправки сообщения/блоков до ответа; `hint`
    ("подсказка") — ответ только что пришёл и не SKIP/не ошибка, держится 4 секунды
    (`flashLogoHint`), потом сам возвращается в `idle`.
  - Превью в браузере сделать не вышло — расширение Claude in Chrome не было
    подключено в сессии, где это делалось; собрано и проверялось сразу в самом
    приложении через `npm run tauri dev` (HMR перезагружает мгновенно).

## Мажорные и минорные обновления — раздельно

Согласовано с пользователем в чате. Разделение по первому числу семвера
(`semverMajor` в `main.ts`): `1.0 -> 1.1` минорное, `1.x -> 2.0` мажорное.

- Два тумблера — "Минорные — ставить автоматом" (по умолчанию включено) и
  "Мажорные — ставить автоматом" (по умолчанию выключено). Состояние — в
  localStorage (`termiinal:auto-update-minor`/`termiinal:auto-update-major`).
  Живут в общем окошке настроек, см. ниже.
- Если для найденного обновления автомат выключен — баннер "Есть
  минорное/мажорное обновление X.Y.Z (сейчас A.B.C). Установить?" с кнопками
  "Установить и перезапустить"/"Позже", как раньше.
- Если включён — баннер "Ставится минорное/мажорное обновление X.Y.Z…" без кнопок,
  скачивание и установка идут сразу, без подтверждения.

## Единое окошко настроек

По просьбе пользователя — задел места под будущие настройки, не только
автообновление. Два равноценных входа в одно и то же окошко (`#settings-modal`),
каждый виден только там, где он единственный способ туда попасть:
- **шестерёнка** (`.settings-gear`) — `position: fixed` в правом верхнем углу окна,
  видна только на стартовом экране (нет сессии — нет и "Дополнительно").
- **"Настройки…"** в "Дополнительно" внутри сессии — дропдаун там чисто сессионный
  (только "Внедрить интеграцию вручную" + ссылка на то же окошко).

Закрывается крестиком, кликом по тёмной подложке мимо самого окошка или Escape.

**"Завершить сессию" и "Дополнительно" переехали в правый верхний угол** (тот же
`position: fixed`, что раньше занимала шестерёнка, см. `.session-corner`) — тоже
по просьбе пользователя, видны только в активной сессии. Шестерёнка на этом экране
скрыта — иначе дублировала бы "Настройки…" из того же "Дополнительно" в паре
сантиметров левее. У `.toolbar-connect` добавлен запас `padding-right`, чтобы
`#status` (прижат к правому краю шапки через `margin-left: auto`) не заезжал под
эту зафиксированную пару — размер запаса подобран без возможности живого превью.
