# Этап 5 — Раздача коллегам (и автообновление)

ТЗ для этого этапа просит только «сборка, инструкция по установке и логину CLI» —
без обновлений вообще. Пользователь явно попросил обновления тоже: с парой друзей и
нерегулярными багфиксами ручная пересылка `.exe` каждый раз неудобна, поэтому сразу
взяли официальный механизм, а не самописный.

## Как это работает

- **`tauri-plugin-updater`** (Rust) + **`@tauri-apps/plugin-updater`** (JS) — проверяет
  `endpoints` из `src-tauri/tauri.conf.json` на `latest.json`, сверяет версию, при
  наличии новой — скачивает и ставит инсталлятор, подпись проверяется локальным
  публичным ключом (тот же `tauri.conf.json`, поле `plugins.updater.pubkey`).
- **`tauri-plugin-process`** — `relaunch()` после успешной установки, чтобы приложение
  перезапустилось на новой версии без ручного действия пользователя.
- **Хостинг релизов — GitHub Releases** конкретного репозитория (публичного — иначе
  клиенту для скачивания нужен был бы GitHub-токен, зашитый в саму программу у
  каждого друга; это обсуждали и осознанно выбрали публичный репозиторий).
- **`.github/workflows/release.yml`** — при пуше тега `v*` собирает Windows-инсталлятор
  (`tauri-apps/tauri-action`), подписывает ключом обновлений и создаёт **черновик**
  релиза на GitHub (`releaseDraft: true`) — чтобы можно было проверить/дополнить текст
  релиза, прежде чем он станет видимым и его подхватит автообновление у уже
  установленных копий.
- **`requireSignedVersion: true`** в конфиге обновлятора — защита от даунгрейд-атаки:
  подпись должна явно содержать ту версию, для которой её делали, иначе обновление
  отклоняется (актуально, раз `latest.json` отдаётся по HTTPS, но сам по себе не
  подписан — подписан только файл инсталлятора).
- **Баннер в `index.html`/`main.ts`** (`#update-banner`) — проверка один раз при старте
  (`checkForUpdatesOnce`), висит поверх всего независимо от того, сессия активна или
  открыт лаунчер. Периодического повторного опроса нет — приложение обычно
  перезапускают, а не держат сутками; если понадобится, добавить легко.

## Ключ подписи обновлений

Сгенерирован локально: `.tauri-keys/terminal-mentor-updater.key` (приватный,
зашифрован паролем) + `.tauri-keys/terminal-mentor-updater.key.pub` (публичный, его
содержимое уже вписано в `tauri.conf.json`). Пароль — `.tauri-keys/updater-key-password.txt`.

**Вся папка `.tauri-keys/` — в `.gitignore`, НИКОГДА не коммитится**, даже в публичный
репозиторий. Если приватный ключ или пароль потеряются — старые установленные копии
смогут обновляться только после генерации НОВОГО ключа и смены `pubkey` в конфиге, то
есть по сути придётся попросить всех переустановить вручную один раз.

## Что нужно сделать руками (не автоматизируется без доступа к GitHub-аккаунту)

1. Создать **публичный** репозиторий на GitHub (например `terminal-mentor`).
2. Подключить его как `origin` и запушить код.
3. В Settings → Secrets and variables → Actions добавить два секрета:
   - `TAURI_SIGNING_PRIVATE_KEY` — содержимое `.tauri-keys/terminal-mentor-updater.key`;
   - `TAURI_SIGNING_PRIVATE_KEY_PASSWORD` — содержимое
     `.tauri-keys/updater-key-password.txt`.
4. Заменить `REPLACE_ME_GITHUB_OWNER` в `src-tauri/tauri.conf.json`
   (`plugins.updater.endpoints`) на реальное имя владельца репозитория.

## Как выпускать релиз

1. Поднять версию в `src-tauri/tauri.conf.json` (`"version"`) и `package.json`.
2. Закоммитить, затем `git tag vX.Y.Z && git push origin vX.Y.Z`.
3. CI соберёт инсталлятор и создаст **черновик** релиза на GitHub — проверить/дополнить
   описание и опубликовать его руками (Publish release).
4. У уже установленных копий при следующем запуске появится баннер «доступно
   обновление», установка — в один клик, с автоперезапуском.

Первую установку (у кого программы ещё нет) это не заменяет — им всё равно нужно один
раз скачать инсталлятор со страницы релиза и поставить вручную; дальше обновления идут
сами.
