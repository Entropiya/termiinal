# Этап 3 — полный цикл обучения

По ТЗ в этот этап входит: режим «Сплит», план, контракт ответа, вставка команд с
очисткой и подсветкой опасного, markdown и mermaid, хранение и экспорт сессий, политики
авто/ошибки/вручную.

Часть этого списка (контракт ответа, markdown+mermaid, политики авто/ошибки/вручную)
по факту уже сделана на этапе 2 — границы в таблице этапов ТЗ ориентировочные, см.
`docs/stage2.md`.

## Сделано

- **Подсветка опасных команд при вставке** (`src/paste-guard.ts`, 12 тестов) —
  перехват `paste` на контейнере `#xterm` в фазе capture (раньше внутреннего
  обработчика xterm.js на его скрытой textarea), построчная проверка вставляемого
  текста по таблице шаблонов из ТЗ (`rm -rf`, `dd`, `mkfs`, запись в `/dev/sd*`,
  `chmod -R 777`, `curl|wget … | sh/bash`, `iptables -P INPUT DROP`, `ufw enable`,
  `ip link set … down`, остановка/правка `sshd`, `reboot`/`shutdown`, запись в `/etc/`).
  При совпадении — баннер с подсветкой красным и явным вторым действием (кнопка
  «Вставить всё равно»), а не автоматическая вставка. Без совпадений — вставка уходит
  в pty сразу, с оборачиванием в bracketed paste, если шелл его включил
  (`term.modes.bracketedPasteMode`).
  - Это эвристика, не песочница: ловит типичную форму команды, как и затирание
    секретов в `redact.ts` — не гарантирует перехват любого обфусцированного варианта.
  - Отступление от буквального текста ТЗ: "второе нажатие" сделано как явная кнопка
    подтверждения, а не повторное `Ctrl+V` — надёжнее отличать от обычной повторной
    вставки и не завязано на то, что именно пользователь нажмёт второй раз.
- **План** (`src/agent-contract.ts`: `parsePlanChecklist`, 4 теста; панель в
  `src/main.ts`/`index.html`) — парсер чек-листа из ```plan блока уже был готов с
  этапа 2, не было подключено только применение: теперь при каждом ответе агента,
  содержащем ```plan, текущий план в приложении целиком заменяется новым снимком
  (ТЗ: агент шлёт полный список, не диф) и рендерится панелью над чатом. Системный
  промпт (`src/system-prompt.md`) уже просил агента про формат — не трогали.
  - Живёт только в памяти текущего запуска приложения — переживание перезапуска и
    экспорт это отдельный пункт ниже (хранение сессий), ещё не сделан.
  - Своя панель (`#pane-plan`), видна одновременно с терминалом и чатом — см. ниже
    про панель задач.
- **Панель задач справа вместо режима «Сплит»** (`index.html`, `src/styles.css`,
  `src/main.ts`: `dockPanes`/`setPaneHidden`) — отступление от буквального текста ТЗ,
  согласованное с пользователем в чате. Вместо трёх жёстких раскладок "Чат"/
  "Терминал"/"Сплит", переключаемых по кругу Ctrl+Shift+M, каждая из четырёх рабочих
  панелей (Терминал, Чат, План, Блоки) прячется/показывается собственной кнопкой-
  подписью (без иконок) в узкой панели у правого края окна, независимо от остальных
  и с запоминанием в localStorage. "Сплит" из ТЗ получается сам собой, когда показаны
  все четыре — не отдельный режим. Кнопка "Режим"/Ctrl+Shift+M убраны как избыточные.
  - Причина: раскладка "Терминал" уже по факту была тем же самым, что просит ТЗ от
    "Сплита" (шелл + чат рядом), только без плана — третий жёсткий режим добавил бы
    кнопку, не добавляя ничего нового по сути. Гибкие тумблеры дают то же самое и
    больше (можно спрятать что угодно, не только чат).
  - Старая кнопка "свернуть Блоки в бок" (`#btn-side-toggle`, сворачивание в узкую
    полосу 2.2rem) заменена той же панелью задач — теперь скрытие полное
    (`display:none`), а не сжатие в полосу. Ключ localStorage для "Блоков" сначала
    был оставлен прежним специально, чтобы не сбросить уже сохранённое у пользователя
    — но при переименовании проекта в `termiinal` все ключи (в т.ч. этот) всё равно
    поменяли префикс на `termiinal:`, см. ниже.
  - **Адаптивная ширина панелей** (`PANE_ORDER`/`setPaneGrow`/`relayoutResizers` в
    `main.ts`) — ширина каждой видимой панели держится через CSS `flex-grow`
    (`flex: N 1 0%`), а не фиксированные пиксели: при изменении размера окна все
    видимые панели масштабируются пропорционально, а не остаются привязанными к
    старой ширине в px. Если видна только одна панель — у неё нет соседей, делящих
    flex-grow, так что она сама занимает всю ширину, без отдельного кода на этот
    случай. Разделители между панелями теперь не статичный один (между терминалом и
    чатом), а пул из N-1 штук, переставляемый между реально видимыми соседями при
    каждом показе/скрытии — так можно потянуть границу между ЛЮБОЙ парой видимых
    панелей, а не только терминал/чат.
- **Маленькое окно "менеджера подключений" а-ля PuTTY, растущее в рабочее при
  коннекте** (`src-tauri/tauri.conf.json`, `src-tauri/capabilities/default.json`,
  `main.ts`: `setSessionActive`) — согласовано с пользователем в чате. Пока сессии
  нет, окно маленькое (460×640) и несворачиваемое по размеру — ровно список пресетов
  и форма нового подключения внутри `.launcher`, без широкой строки полей в шапке.
  При успешном подключении (`setSessionActive(true)`) окно становится resizable и
  растёт до рабочего размера (1280×860), в шапке вместо формы — короткое саммари
  (имя/адрес хоста) и кнопка "Завершить сессию"; при её нажатии или выходе процесса
  (`onExit`) окно сжимается обратно. Это одно и то же окно ОС, не два разных — хотя
  по ощущениям ближе к тому, как PuTTY открывает отдельное окно сессии, а менеджер
  подключений закрывает.
  - Поля редактирования подключения (пресет/адрес/ключ/кнопки сохранить-удалить)
    физически перенесены из шапки внутрь `.launcher` — та же логика в `main.ts`
    (поля находятся по `id`, их расположение в DOM ей не важно), просто вертикальная
    форма вместо широкой горизонтальной строки, которая не влезла бы в 460px.
  - Повторный запуск `.exe` даёт параллельную независимую сессию без доп. кода — в
    проекте нет `tauri-plugin-single-instance`, Tauri по умолчанию не ограничивает
    число запущенных окон одного приложения.
  - Разрешения `core:window:allow-set-size`/`allow-set-resizable`/`allow-set-title`/
    `allow-center` добавлены явно в capability — `core:default` их не включает (там
    только read-only команды вида `allow-inner-size`, без `allow-set-*`).
  - **Доведено по дальнейшей просьбе пользователя**: верхний бар целиком скрыт, пока
    сессии нет — "Дополнительно" и статус нужны только внутри сессии, а кнопка
    "Подключиться" переехала в саму форму лаунчера (`#btn-connect`, отдельная от
    `#btn-ssh`, у которой теперь одна роль — "Завершить сессию"). Убран `<select>` со
    списком пресетов из формы — он подставлял в поля значения уже сохранённого
    пресета для редактирования, что и было источником путаницы "почему тут что-то
    уже заполнено"; теперь форма всегда про новое подключение, открыть сохранённый
    пресет — клик по нему в списке лаунчера (как и было), удалить — крестик там же
    (кнопка удаления у `<select>` была чистым дублем). Добавлен `btn-preset-save`
    без привязки к выбору — "Сохранить как пресет" всегда создаёт новый пресет.
  - **Выбор файла ключа через системный проводник** — добавлен Tauri-плагин
    `tauri-plugin-dialog`/`@tauri-apps/plugin-dialog` (его не было в проекте),
    разрешение `dialog:allow-open` в capability, кнопка "Обзор…" рядом с полем пути
    к ключу вызывает `open({ directory: false })` и подставляет выбранный путь.
  - **Ещё раунд правок по месту** (тот же разговор): форма "Новое подключение"
    очищается после реального отключения (`clearPresetFields()` в `onExit` у pty, не
    в `setSessionActive` — иначе обнулялись бы и дефолты при самом первом старте
    приложения, когда никакой сессии ещё не было вообще); визуально отделена от
    списка пресетов рамкой-разделителем и собственным заметным заголовком (было —
    тот же мелкий серый стиль, что у "Сохранённые подключения", всё сливалось);
    панель задач в сессии сужена с 6rem до ~1.9rem — подписи идут вертикально
    (`writing-mode: vertical-rl`), панель теперь не отъедает заметную долю ширины у
    рабочих панелей.
  - **Локаль Git Bash** — MSYS2 сама подставляла `LANG` под язык интерфейса Windows
    (ru-RU у пользователя), если переменная не задана явно — отсюда русские
    сообщения coreutils/bash в локальном шелле. Теперь `spawnGitBash` явно передаёт
    `LANG=C.UTF-8`/`LC_ALL=C.UTF-8`, что отключает это автоопределение.
    Для SSH-сессий это не тот же механизм: проверено (`ssh -G ...`), что ни системный,
    ни пользовательский `ssh_config` на этой машине не форвардят `LANG`/`LC_*` на
    удалённую машину (`SendEnv`/`SetEnv` не заданы), и в окружении самого приложения
    этих переменных тоже нет — значит, язык вывода на удалённой машине уже определяется
    только её собственной локалью, а не этим приложением. Если по SSH всё равно видно
    русский — это локаль самого удалённого хоста, лечится там (`dpkg-reconfigure
    locales` и т.п.), не в этом коде.

  (ash/dash) — у проекта пока нет отслеживания "сейчас bash или ash/dash" в принципе
  (есть только ОС из пробы хоста, не конкретный шелл). Сейчас многострочная вставка
  всегда уходит как есть во всех шеллах.
- Хранение и экспорт сессий (JSON-формат из ТЗ, экспорт в markdown) — без этого план
  и лог блоков пропадают при перезапуске приложения, хотя ТЗ прямо говорит, что
  рабочая сессия "не привязана к окну: её можно закрыть и продолжить в другом окне
  или после перезапуска".
